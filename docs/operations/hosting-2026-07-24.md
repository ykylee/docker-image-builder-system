## 1. 한눈에

빌드된 이미지가 k8s 에 **지속 호스팅**되고 `http://<HOSTING_BASE_HOST>/<context-path>/` 로 접근·관리된다(평문 HTTP — HTTPS 미도입).

```
POST /builds (contextPath?, runtimePort?, stripPrefix?)
  → 서버가 context-path 할당(정규화/유일성) + build 에 저장
  → runner claim(contextPath/runtimePort/stripPrefix 수령)
  → 이미지 빌드 → 컨테이너 테스트 → k8s 배포(Deployment+Service+Ingress+APP_BASE_PATH)
  → 서버가 배포 성공 보고로 HostedService upsert(url 조립)
운영: GET/POST/DELETE /admin/hosted-services (또는 UI /admin/hosting)
```

## 2. 설정 (env)

| 컴포넌트 | env | 의미 |
|---|---|---|
| runner | `RUNNER_K8S_MODE=k8s` | k8s 배포 활성(§[k8s 배포 문서](./k8s-deploy-webhook-2026-07-24.md)) |
| runner | `RUNNER_K8S_CLUSTER` | kubeconfig context |
| build-server | `HOSTING_BASE_HOST` | 호스팅 URL host(설정해야 HostedService upsert — opt-in) |
| build-server | `HOSTING_KUBE_CONTEXT` | 관리(scale/delete) kubectl context |
| build-server | `HOSTING_KUBECTL_BIN` | kubectl 실행 파일(기본 kubectl) |

전제: 클러스터에 **ingress-nginx**(또는 호환 Ingress 컨트롤러). runner/build-server 실행 환경에 `kubectl` + kubeconfig.

## 3. 빌드 요청 필드

| 필드 | 기본 | 의미 |
|---|---|---|
| `contextPath` | appName 정규화 | URL prefix(전역 유일, 예약어 회피) |
| `runtimePort` | 8080 | 앱 컨테이너 listen 포트 |
| `stripPrefix` | true | Ingress prefix strip 여부([sub-path 문서](./hosting-sub-path-2026-07-24.md)) |

앱은 `APP_BASE_PATH=/<context-path>/` env 를 읽어 emit URL 에 prefix 를 붙여야 한다(§sub-path).

## 4. 관리 (admin)

| 동작 | API | k8s |
|---|---|---|
| 목록 | `GET /admin/hosted-services` | registry(SSOT) |
| 상세 | `GET /admin/hosted-services/:appName` | registry |
| 중지 | `POST /admin/hosted-services/:appName/stop` | `kubectl scale --replicas=0` → STOPPED |
| 재개 | `POST /admin/hosted-services/:appName/start` | `kubectl scale --replicas=1` → RUNNING |
| 제거 | `DELETE /admin/hosted-services/:appName` | `kubectl delete deployment,service,ingress` + registry 제거(context-path 반환) |

UI: `/admin/hosting`(Hosting 탭). 관리 kubectl 은 **build-server 가 직접 shell-out**(runner=배포 생성, build-server=수명 관리).

## 5. e2e

```bash
# kind + kubectl + docker 환경에서
bash apps/runner/scripts/e2e-hosting.sh
```

- Phase A(라우팅): kind + ingress-nginx + `examples/hosted-base-path-app` → 실제 `host/<cp>/` 접속 + `APP_BASE_PATH` 자산 로드 실측.
- Phase B(관리): 실 K8sAdmin 으로 stop(scale 0) + remove(delete) 실측.
