### 1.2 정지작업 2 — live 엔드포인트 / read-only 엔드포인트 분류 (Plan)

**핵심 발견**: P2-M2 의 변경 대상 endpoint 들이 두 종류로 나뉘며 각각 영향이 다르다.

#### 1.2.1 Live endpoint (runner 가 실제로 호출)

| Path | Method | Go client | 용도 |
|------|--------|-----------|------|
| `/builds/:buildId/preview` | POST | `QueueTestDeployment` | 컨테이너 테스트 시작 — build-server 가 runner 에게 테스트 큐잉 위임 |
| `/builds/:buildId/test-deployment/ready` | POST | `ReportPreviewReady` | 컨테이너 ready + runtime URL 보고 |
| `/builds/:buildId/test-deployment/status` | POST | `ReportPreviewStatus` | PROVISIONING / FAILED / EXPIRED 보고 |

- `apps/runner/internal/hostclient/build_control_client.go` 가 위 3종을 모두 호출.
- runner 호출 페이로드는 JSON 본문에 `previewUrl` 필드를 들고 다닌다 (Go: `PreviewURL`).
- **이 endpoint 들은 그대로 유지**하되 **payload 의 `previewUrl` → `runtimeUrl` 로 정렬**.
- path `/preview` 의 의미를 명확히 — `preview` 라는 단어가 더 이상 preview-era 의미가 아니므로 `/container-test` (또는 동등 canonical) 로 **path 도 canonical 화** 검토.

#### 1.2.2 Read-only endpoint (consumer 0)

| Path | Method | Consumer | 판정 |
|------|--------|----------|------|
| `/builds/:buildId/test-deployment` | GET | **build-monitor 0건** (BuildDetail.tsx 의 주석만 인용), skill_mcp 0건, e2e 0건 | **즉시 제거** |

- TASK-160 에서 정의한 `build_test`(ContainerTestResult) 가 canonical 이고 이 endpoint 의 `TestDeployment` 와 중복.
- 이 endpoint 를 제거하면 `previewStatuses` enum 의 정당성도 함께 사라진다 (사용처 0).
