### 7.3 설계 판단 2건

1. **스키마는 `.loose()`** — 라우트들이 상황별 진단 필드를 함께 싣는다
   (`header` / `callerId` / `expected` / `actual` / `reason` / `runnerId` …, 실측 10여 종).
   닫으면 기존 응답이 깨지고 운영 진단 정보가 줄어든다. 계약이 고정하는 것은
   "모든 에러에 `message`, 검증 실패에 `issues`" 두 가지로 한정.
2. **타입은 좁게 (`Pick` / 명시적 interface)** — `.loose()` 는 생성 타입에
   `& { [key: string]: unknown }` index signature 를 만들고, **이게 있으면 오타든 필드명
   변경이든 `unknown` 으로 통과해 타입 검증이 무력화된다**. 그래서:
   - shared-contract: `ApiErrorResponse` 를 명시적 interface 로 두고
     `AssertEnvelopeMatchesSchema` 로 zod 스키마와의 일치를 컴파일 타임에 고정
   - frontend: `Pick<components["schemas"]["ApiErrorResponse"], "message" | "issues">`

   > 첫 구현은 `z.infer` 를 그대로 썼고, **검증 실험에서 계약 위반이 잡히지 않아** 이
   > 문제를 발견했다. "타입을 도입했다" 와 "타입이 실제로 잡는다" 는 다르다.

### 9.1 P0 — Astryx 디자인 토큰 하이재킹 (근본 원인)

`@astryxdesign/theme-neutral` 이 **우리와 이름이 같은 토큰 3종**을 재정의한다:

| 토큰 | `:root` (tokens.css) | 컴포넌트 위치 실측값 |
|---|---|---|
| `--color-text-primary` | `#0f172a` | `light-dark(#171717, #fafafa)` |

하위 전체에 상속시키므로 tokens.css 값이 컴포넌트 위치에서 덮인다. 동시에 하위

분기**를 골랐다.

브랜드명 · `@admin` 배지 · 필터 칩이 화면에서 사실상 사라진 상태. **기본 테마가

**왜 오래 잠복했나**: 라이트 모드에서는 `#171717` 이 밝은 배경 위 어두운 글자라

이뤄져 왔다. 또한 `tokens.css` / `theme.css` 주석이 "우리 React 컴포넌트는 본
layer 의 token 을 사용하지 않으므로 visual 영향 0" 이라고 **단언**하고 있었고,
그 단언이 가장 많이 쓰는 텍스트 토큰에서 정확히 틀렸다.

**조치**: `<Theme>` 래퍼 + `theme.css` 제거. 근거 — Astryx 컴포넌트 import 사용처가
`main.tsx` 외 **0건**이라 보호할 default 컴포넌트 스타일이 없고, reset 은
`globals.css` 가 자체 보유 (box-sizing / margin / color-scheme).

### 9.2 P1 — 페이지 셸 부재

루트(`#app-react`)에 padding 만 있고 페이지마다 `max-width` / `padding` /
`calc(100vh - ...)` 를 제각각 하드코딩하고 있었다.

### 9.3 P2 — SPA 딥링크가 동명 API route 에 가려짐

주소창으로 `/builds` 진입 시 화면 대신 원시 JSON, `/admin/builds` 는 401 JSON.
**등록된** 경로라 `setNotFoundHandler` 로는 잡히지 않아 라우팅 이전 단계인
`onRequest` 훅에서 분기했다.

판정 기준은 **`Sec-Fetch-Dest: document`** — 브라우저 문서 내비게이션에만 붙고
fetch/XHR(`empty`) · iframe(`iframe`) · Go runner(미전송) 와 구분된다. 사용자 결정으로
4개 선택지(헤더 분기 / SPA `/app/*` 이동 / API `/api/*` 정식 이전 / 현행 유지) 중
**무중단·비파괴**인 헤더 분기를 채택. runner 가 bare `/builds/claim` 을 쓰고 있어
API 경로 이전은 runner + e2e 11종 + 문서 동시 수정이 필요한데 Docker 부재로 e2e
검증이 불가하다는 점이 결정 근거.

`/api/` · `/openapi` · `/docs` · `/health` · `/assets/` 는 가로채지 않는다.

실서버 확인:

| 요청 | 결과 |
|---|---|
| 주소창 `/builds` · `/admin/builds` · `/builds/<uuid>` | **SPA 렌더** (이전 JSON / 401) |
| `GET /builds` (헤더 없음) | JSON — 계약 무변경 |
| `POST /builds/claim` (runner) | 400 JSON — 계약 무변경 |
| `/docs` · `/health` 주소창 진입 | Swagger / JSON 그대로 |
| `/api/builds` | 307 → `/builds` 유지 |

**한계**: `Sec-Fetch-*` 미지원 클라이언트(구형 브라우저)는 종전대로 JSON 을 받는다.
헤더 기반이라 규칙이 암묵적이므로 회귀 가드로 양방향(가로챔 / 미가로챔)을 고정했다.

### 13.3 구현

- **`theme.ts` 신규** — `defineTheme({ name: "dib", tokens: { "--color-accent": [light, dark] } })`.
  이식 토큰은 **1종**. 텍스트/배경/테두리 대비와 상태색은 업스트림에 위임한다 —
  이식이 적을수록 pre-1.0 churn 에 덜 흔들리고, Astryx 컴포넌트 조합 안에서의 접근성을
  우리가 계속 책임지지 않아도 된다.
- **`themeStore.ts` 신규 (Zustand)** — 테마 상태를 ThemeToggle 지역 state 에서 끌어올렸다.
  Astryx `<Theme mode>` 가 App 보다 **위**(main.tsx)에서 같은 값을 봐야 하기 때문.
  DOM 반영(`data-theme` + `color-scheme`)과 localStorage 영속화도 함께 이관 — 이전에는
  ThemeToggle 이 렌더링과 부수효과를 같이 들고 있어 **토글 버튼이 없는 페이지에서는
  테마가 적용되지 않을 여지**가 있었다.
- **`main.tsx`** — `astryx.css` import + `<Theme theme={dibTheme} mode={mode}>` 로 App 을 감싸는
  `ThemedApp` 도입. `mode="system"` 을 **쓰지 않고** store 값을 명시적으로 내린다 —
  Astryx 내부가 `light-dark()` 를 쓰므로 mode 가 어긋나면 페이지는 다크인데 Astryx
  컴포넌트만 light 로 렌더된다 (P0 와 같은 계열의 증상).
- **`theme.test.ts` 신규** — 브랜드 색이 `theme.ts` 와 `tokens.css` 양쪽에서 일치하는지 고정.
  이관이 끝날 때까지 두 체계가 공존하므로, 어긋나면 **같은 화면에 두 가지 인디고**가 보인다.

### 13.4 테스트 조정 (동작 이전에 따른 정당한 갱신)

`ThemeToggle.test.tsx` 2건이 깨졌고, 원인이 서로 달랐다.

1. **store 싱글턴 누수** — 앞 테스트가 light 로 끝나면 다음 테스트의 첫 클릭이 dark 로

### 14.4 사전 결함 + 보강 4건

1. **`Button`/`Badge` 는 children 이 아니라 `label` prop** — TSC 가 잡았다

2. **jsdom 25 는 `HTMLDialogElement.showModal()` 을 구현하지 않는다** —

   영역이므로 실브라우저에 맡긴다고 주석에 명시.
3. **~~`data-testid` 가 래퍼에 붙어 `fireEvent.change` 가 먹지 않았다`~~ — 오기.
   TASK-138 착수 중 실측으로 반박됐다.** Astryx `TextInput` 은 `data-testid` 를

   도 정상 동작한다 (원래 질의로 되돌려 재현 → 통과). 당시 4건 실패는

   `onClose`)이었는데, 그 Escape 실패를 성공 테스트 실패로 잘못 읽고 원인을
   지어낸 것이다. **실패 목록을 정확히 읽지 않고 원인을 추정한 것이 잘못.**
   `getByLabelText` 로 바꾼 것 자체는 유지한다 — 구조 결합이 줄고 AT 기준과
   같아지는 정당한 개선이지만, 그것이 **당시 실패의 원인은 아니었다.**
4. **Escape 의 리스너 위치가 바뀌었다** — 이전에는 `window`, Astryx 는

   테스트를 정정. **의도(Escape 로 닫힘)는 유지, 발화 지점만 사실에 맞춤.**

### 17.5 자기 정정 2건 — 둘 다 측정 오류

이 TASK 에서 "이관이 깨졌다" 고 두 번 잘못 판단했고, 둘 다 **제 측정 방법이

1. **"토크나이저가 프로덕션에서 동작하지 않는다"** — DOM 에서 `astryx-token-*`

   ```js
   useSpans = highlightMode==='spans' || (auto && !hasHighlightAPI()) || (auto && isSafari())
   ```

   jsdom 은 CSS Custom Highlight API 가 없어 **span 경로**, Chrome 은 API 가
   있어 **Range 기반 `::highlight()` 경로**를 쓴다. 즉 DOM 은 평문이고 색은
   Highlight API 가 입힌다. `CSS.highlights.size === 2` 로 확인했고 화면에서도
   색이 정상이었다. **span 이 없다 ≠ 색이 없다.**

   → 부작용: `LogStream.test.tsx` 의 색 검증은 **span 폴백 경로**를 검사한다.
   토크나이저 출력이 맞는지는 확인하지만 Chrome 사용자가 보는 경로는 아니다.
   테스트에 그 사실을 주석으로 남겼다.

2. **"라이트 모드에서 배경이 흰색이라 다크 고정이 안 먹는다"** — 바깥 컨테이너를

### 22.1 감사 방법

### 22.2 감사가 발견한 실제 회귀 — Astryx 버튼 배경 소실

정적 스캔은 후보만 줬다 (bare 클래스 5개: .badge/.banner/.chip/.form/.grid).
클래스 충돌 **실측은 0건**. 그런데 **globals 의 bare `a`/`button`** 을 실측하니
진짜 문제가 나왔다:

- Astryx TopNavItem(`<a>`) 의 color 가 우리 `--dib-color-accent-primary` 로 덮임
- **Astryx Button(`<button>`) 의 background 가 우리 `button { background: none }`
  으로 덮여 사라짐**

실브라우저 확인: BuildRequest 의 **Submit Build**(Astryx primary) 와
RegisterRunnerModal 의 **Register**(Astryx primary) 가 **배경 없이 회색 텍스트**로
렌더되고 있었다. **모든 Astryx primary/secondary 버튼이 배경을 잃은 상태.**

**근본 원인 — unlayered × element 셀렉터**: 우리 CSS 는 Astryx 의 @layer 보다
우선하는 unlayered 다. `button {}` 은 element 셀렉터라 Astryx 의 `<button>` 에도
적용되고, **unlayered 라 specificity 무관하게 Astryx atomic 을 이긴다.** 그래서
`background: none` 이 primary 배경을 없앴다. TASK-137(Dialog 이관) 때부터 있던
회귀인데 그동안 못 봤다.

**오판 정정**: 처음엔 `:where()` 화가 원인이라 의심했으나, 원복 후에도
transparent 라 `:where` 무관임이 드러났다 (specificity 가 아니라 layer 문제).

### 22.3 수정

`a`/`button` base reset 을 **`:not([class*="astryx-"])`** 로 Astryx 요소를 매칭에서
제외. unlayered 라 specificity 로는 못 막으므로 아예 셀렉터가 Astryx 를 안 잡게
한다. 순수/우리 요소에는 base 가 그대로 적용된다.

실브라우저 확인: Submit Build 배경 `rgb(126,129,243)`(브랜드 인디고) + 흰 글자로
**복구**. Reset form(secondary)도 회색 배경 정상. 순수 `<a>` 도 base 인디고 유지.

bare `iframe`(ApiConsole.css)도 `.frame-wrap iframe` 으로 스코프.

**실증**: iframe 을 bare 로 되돌리니 lint 가 정확히 실패, 스코프 후 통과.

정적으로 판정 불가한 **실제 클래스 충돌**(우리 규칙이 Astryx 요소에 붙는가)은

### 23.1 왜 필요한가

**정밀화 (오탐 제거)**: 초판이 "클래스 이름 존재"만 보고 `.md`(주석 `DESIGN.md`
오인) / `.secondary`(우리는 `.preset-btn.secondary` 복합으로만 씀)를 오탐했다.
→ 주석 제거 + **단독 클래스 셀렉터**(`.class` 또는 `.class:pseudo` 하나로만
이뤄진 규칙)만 수집하도록 고쳤다. 복합/자손 셀렉터는 조상·형제 클래스가 함께
