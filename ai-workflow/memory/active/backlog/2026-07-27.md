### 1.1 문제

`.github/workflows/nightly-e2e.yml` 의 `hosting-e2e` 잡은 **이미 봉인(TASK-171)** — `schedule` + `workflow_dispatch` 에서만 돌고 `kind + ingress-nginx` 실 라우팅 + 관리 라이프사이클을 검증한다. 그러나 **운영자 / AI 에이전트가 잡의 신호 강도 / 환경 / 트러블슈팅을 한 곳에서 참조할 운영 가이드가 없었다** — 13종 e2e 스위트에는 호스팅 e2e 가 빠져 있어 별도 잡으로 분리된 경위, main push 가 의도적으로 제외된 이유, kind + ingress-nginx 사이클이 문서로 정합돼 있지 않았다.

### 1.2 결정 (Decide)

- 옵션 A (채택): **운영 가이드 1종 신규** — workflow 변경 0. 잡 구조 + env + 로컬 재현 + 트러블슈팅만 문서화. workflow 자체가 이미 봉인된 본질 변경이 아니므로 **스크립트 / SQL / schema / migration / version / git tag 모두 변경 0**.
- 옵션 B (기각): 잡에 트리거/단계 추가 (예: main push 에서도 trigger / artifact 업로드) — 본 세션의 사용자 결정은 "CI 실측 검증(로컬) + 운영 가이드 갱신" 으로 옵션 A 스코프 한정.
