### 1.1 문제 (Problem)

- frontend rewrite 시리즈 (TASK-088~094) + M4.5 Group A~D (TASK-095~098) 가 완료되어 React 측가 primary SPA 이지만 디자인 토큰이 두 시스템에 분산:
  - **Svelte 측** (`apps/build-monitor/src/lib/tokens.css`, 134 lines) — 자체 디자인 토큰 시스템 (`--color-bg-canvas`, `--color-text-primary`, `--shadow-card` 등 60+ 토큰) + light/dark 모드 + 운영 검증 완료 (TASK-046 follow-up, TASK-083, TASK-090 의 디자인 토큰 정렬).
  - **React 측** (`apps/build-monitor/react/src/theme.css`, 62 lines) — Astryx v0.1.4 의 reset.css + astryx.css + theme-neutral theme.css 3-layer @import cascade. 일부 Svelte 토큰 (`--color-bg-canvas`, `--color-text-primary`, `--spacing-8`, `--font-family-sans`, `--color-background-body` 등) 을 `var(..., fallback)` 형태로 cross-reference.
- React 측 globals.css 의 html/body 가 `var(--color-bg-canvas)` / `var(--color-text-primary)` / `var(--font-sans)` 를 사용하지만, Astryx theme-neutral 은 그 이름의 토큰을 노출하지 않음 → 결과적으로 Svelte tokens.css 가 import 되지 않으면 모두 `transparent` / `inherit` fallback 으로 떨어짐.
- cross-framework 공존 상태 (TASK-095 결정 옵션 A) 에서는 Svelte 가 `tokens.css` 를 import 하고 React 가 `theme.css` 만 import 하기 때문에 **React 측 디자인이 Svelte 토큰을 사용하지 못하는 잠재 결함**.
- TASK-096 (StatusPill 디자인 토큰 baseline 정합) 이 component-level 보강에 그쳤고 디자인 시스템 단일화는 본 TASK scope.

### 1.2 결정 (Decision)

- **옵션 A (채택)**: Svelte tokens.css 단일 source-of-truth.
  - `apps/build-monitor/src/lib/tokens.css` (Svelte baseline) 가 design tokens 의 single source-of-truth.
  - React 측 build 시점에 Svelte tokens.css 를 동일하게 import (Vite 의 path alias 또는 별도 styles 디렉터리 symlink/copy).
  - `apps/build-monitor/react/src/theme.css` 의 Astryx `@import` 3종은 **제거**. Astryx 컴포넌트 미사용 (현재 React 측은 직접 만든 `.css` + 인라인 style 사용) 이므로 Astryx layer 가 불필요.
  - React 측가 Svelte tokens.css 의 모든 변수 (`--color-*` / `--size-*` / `--font-*` / `--space-*` / `--radius-*` / `--shadow-*` / `--motion-*` / `--z-*` / `--code-*`) 를 fallback 없이 직접 사용.

- 옵션 B (rejected): 양쪽 디자인 시스템 병행 유지 — 장기 토큰 drift 위험.
- 옵션 C (rejected): 통합 파일 추출 — `shared/design-tokens.css` 신규 추출. 단일화 효과는 동일하나 파일 1개 더 만들지 않고 Svelte tokens.css 자체를 단일 source 로 채택하는 게 운영 검증된 시스템 활용 + 신규 파일 0개.

### 1.4 사전 결함 + 보강 (예상)

1. **Vite 의 css import 경로** — React 측이 `apps/build-monitor/src/lib/tokens.css` 를 import 하려면 Vite alias 또는 상대 경로 필요. `vite.react.config.ts` 의 `resolve.alias['@']` 와 정합하는 path 사용.
2. **PostCSS / build pipeline** — Svelte tokens.css 가 css 변수 + `@media (prefers-color-scheme: dark)` 등 단순 변수 정의만 하므로 PostCSS 영향 없음. 정합 확인.
3. **light/dark 모드 data-attribute 적용** — ThemeToggle 이 `document.documentElement.setAttribute('data-theme', 'light' | null)` 으로 적용. Svelte tokens.css 가 `:root[data-theme="light"]` 로 cascade. React 측도 동일 패턴 유지 — 변경 없음.
4. **Astryx `@layer` cascade 제거 후 component styling** — React 측가 현재 Astryx 컴포넌트 (`Button`, `VStack`, `Theme` 등) 를 직접 사용하지 않고 자체 `.css` + 인라인 style 만 사용 (확인 필요). Astryx 3-layer @import 가 실제 React 측 스타일에 기여하는 부분이 0 이어야 theme.css 의 import 제거가 무영향.
5. **`@astryxdesign/core/reset.css`** — box-sizing, margin 리셋 등. React 측 globals.css 의 `*, *::before, *::after { box-sizing: border-box; }` 가 이미 자체 정의. reset.css 대체 가능.
