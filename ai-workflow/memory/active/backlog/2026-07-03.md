### 28.2 결정 (Decisions)
- **A. session store 는 Writable 대신 custom SessionStore** — `set` 만 노출하고 `update` (함수형 갱신) 는 의도적 봉인. `Writable` 인터페이스는 그대로 두면 코드 어디서든 `userIdStore.update(prev => ...)` 로 변조 가능 → Login/AdminLogin 의 submit 으로만 바뀌어야 한다는 invariant 가 새어나갈 수 있음. SessionStore 로 좁혀 type system 으로 잠금.
- **B. `subscribe` 시 lazy read** — module load time 의 `readInitial` 결과에 영구 묶이지 않게, 첫 구독 시점에 localStorage 를 다시 읽는다. 테스트 격리 (render 전에 setItem 한 값 인식) + production 첫 구독이 module load 보다 늦을 수 있는 경우 모두 자연스러움.
- **C. appName 의 source of truth 는 BuildRequest/BuildSummary schema** — admin 쪽 `AdminUserBuildSummary` 는 BuildSummary.extend 이므로 자동 전파 (PR #9 M4 의 evolve contract 그대로). repository 는 schema 가 받으면 그대로 저장/응답.
- **D. postgres 1차는 metadata->>'appName' 으로 처리** — DB 컬럼 추가 없이 1차 골격이 굴러가게 한다. 사용자 지시로 `projectId`/`repositoryId` 컬럼은 비워두고 마이그레이션은 후속 PR. admin 쪽에서도 `appName` 만 채워서 응답하므로 UI 영향 없음.
- **E. generated/openapi.d.ts 손 갱신** — predev/prebuild hook 이 live build server 에 붙지 못하면 generator 가 skip/fail 되므로, contract 변경 후 generator 가 한 번도 안 도는 환경에서도 type 이 맞도록 직접 갱신. PR #9 follow-up 코멘트(S2) 의 "generator 가 CI hard gate 가 될 때까지" 가정이 아직 유효하므로 같은 방식 유지.
