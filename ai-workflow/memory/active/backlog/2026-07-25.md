### 1.1 문제

v0.7.0 봉인 직후 v0.8.0 후보로 분류된 k8s adapter 확장 묶음. v0.7.0 까지
남아 있던 운영 결함 3종을 옵트인/내부 보강으로 해소한다.

- **E1 Per-build namespace 미분리** — `kubectlDeployer.Deploy()` 가 단일
  공유 namespace(`RUNNER_K8S_NAMESPACE`) 만 지원. 빌드 간 ingress DNS
  충돌 가능 + audit 어려움.
- **E2 Ingress cleanup 누락** — `kubectlDeployer.Cleanup()` 이
  `delete deployment,service` 만. 동명 재빌드 시 stale Ingress 가 라우팅을
  잡아채는 잠복 결함.
- **E3 k8s 실패 시 docker registry 결과 손실** — `build_service.go:380`
  분기에서 k8s Deploy 실패 시 `TargetType=K8S` FAILED 만 보고하고 docker
  registry 결과(`targetRef`/`resultRef`)가 사라진다. registry push 는
  성공한 채로 k8s 배포만 실패한 케이스에서 결과 조회 불가.

### 1.2 결정 (Decide)

진입 결정 2종 (사용자 결정):

- **E1 옵트인(default=false)**: `RUNNER_K8S_NAMESPACE_PER_BUILD=true` 면
  buildID 별 namespace(`dib-<buildID>`) 로 격리. 기존 운영자 설정 호환.
- **E3 마지막 FAILED + cause**: docker registry 결과를 payload에 보존한
  채 `FAILED(K8S)` 단일 보고. errorMessage 에 "docker registry push
  survived: <ref>" 포함. registry 자동 cleanup 은 본 단계 범위 밖.

### 1.3 구현 (Implement)

#### 1.3.1 E1 — per-build namespace 옵트인

- `apps/runner/internal/config/config.go`: `K8sNamespacePerBuild bool` 추가,
  `parseBool()` 헬퍼(accepts `true/1/yes/on` / `false/0/no/off` / default).
- `apps/runner/internal/services/build_service.go`: `deployImage()` 의 k8s
  분기에서 `RUNNER_K8S_NAMESPACE_PER_BUILD=true` 면 ns =
  `dib-<buildID>`(DNS-1123 정제). 헬퍼 `dns1123Label()` (deploymentName
  규약과 동형, 53자 + 양끝 trim).
- 기본값(false)은 기존 `RUNNER_K8S_NAMESPACE`(기본 `dib-builds`) 공유.

#### 1.3.2 E2 — Ingress cleanup

- `apps/runner/internal/deploy/k8s_kubectl.go` `Cleanup()`: `delete
  deployment,service` → `delete deployment,service,ingress` 한 명령으로
  묶음. `--ignore-not-found` 유지(Ingress 없는 정상 케이스 안전).
- 같은 deploymentName(`dib-<buildID>`) 으로 Ingress 가 생성되므로 한
  명령으로 정리 가능.

#### 1.3.3 E3 — k8s 실패 시 docker registry 결과 보존

- `apps/runner/internal/services/build_service.go` `deployImage()`:
  - k8s 분기 시작에 `IN_PROGRESS(K8S, deliveryMode=POLLING)` 보고(best-effort).
  - k8s Deploy 실패 시 `payload.dockerRegistry = {targetRef, resultRef,
    survivedAt: now.UTC()}` 추가 + `FAILED(K8S, ErrorCodeDeploymentFailed)`
    보고. `ErrorMessage` 에 `k8s deploy failed: <원인> (docker registry
    push survived: <ref>)` 표기.
- docker registry 성공 결과를 인라인 보존(policy: 마지막 FAILED + cause).
